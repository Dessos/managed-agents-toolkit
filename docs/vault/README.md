# `docs/vault/` — Knowledge vault for cma

> Operator's bench, tools, and light. The persistent surface where decisions,
> learnings, session context, and cached reference material live so they
> survive across sessions, agents, and humans.

## The three-layer architecture

This vault works **alongside** `CHANGELOG.md` and `manage_adr` (codebase-memory-mcp). Each layer answers a different question — they do not duplicate.

| Layer | Path / Tool | Question it answers | Update cadence |
|---|---|---|---|
| Release snapshot | [`../../CHANGELOG.md`](../../CHANGELOG.md) | "What was decided at v0.5.0?" | Append-only at release time; immutable |
| Decision history | [`decisions/`](decisions/) | "Why did we decide X, and is it still valid?" | Per decision; revisitable via `reviewed_on` |
| Architectural summary | `mcp__codebase-memory-mcp__manage_adr` | "What's our current PURPOSE / STACK / ARCHITECTURE / PATTERNS / TRADEOFFS / PHILOSOPHY?" | When an ADR materially shifts current state |

CHANGELOG is a snapshot in time; ADRs are the living explanation; `manage_adr` is the queryable summary. They never drift because they answer different questions.

## When to write what (the decision tree)

```
A new thing came up — what kind of note is it?

├── It's a *decision* between alternatives (we chose X over Y)?
│   └── `cma vault new-decision <slug>` → fills `decisions/`
│
├── It's a *finding* from a failure or experiment ("X is brittle because Y")?
│   └── `cma vault new-learning <slug>` → fills `learnings/`
│
├── It's a *backtest / measurement* result?
│   └── `cma vault new-evaluation <slug>` → fills `evaluations/` (Tier 2)
│
├── It's an *incident postmortem*?
│   └── `cma vault new-incident <slug>` → fills `incidents/` (Tier 2)
│
├── It's *current sprint state* the next agent should know?
│   └── Edit `context/ai-session-brief.md` directly
│
└── It's an *outside reference* (e.g., a doc page)?
    └── Add it to `knowledge/` (e.g., `cma vault refresh-knowledge` for Anthropic docs)
```

## Frontmatter contract

Every `.md` file in this vault carries YAML frontmatter:

```yaml
---
type: decision | learning | evaluation | incident | context | governance | knowledge | meta
status: active | superseded | archived | draft
created: YYYY-MM-DDTHH:mm:ssZ
updated: YYYY-MM-DDTHH:mm:ssZ
tags: [...]
related: [[wikilinks-to-other-notes]]
confidence: high | medium | low
source: "<provenance: file path | URL | CHANGELOG line range | conversation date>"

# Optional, validated when present:
reviewed_on: YYYY-MM-DD            # required for ADRs older than 90d
supersedes: [filename.md, ...]
superseded_by: filename.md
superseded_reason: "<prose>"
fetched_at: YYYY-MM-DDTHH:mm:ssZ   # REQUIRED for type:knowledge with HTTP source
upstream_etag: "<hash>"            # optional, cache-busting hint
---
```

The vault linter (`cma vault lint`) enforces this. Drift = lint error.

## Anti-decay enforcement (the hooks)

Four Claude Code hooks wired in `.claude/settings.json` keep the vault honest:

| Hook | When | What |
|---|---|---|
| `SessionStart` | Every session start | Reads `context/ai-session-brief.md` + last 5 ADRs into context |
| `PreToolUse[git commit]` | Before any `git commit` | **Blocks** if CHANGELOG adds a "Decisions baked in" bullet without a parallel ADR file staged |
| `PostToolUse[git commit]` | After successful commit | Nudges to update `manage_adr` if the committed ADR touches one of the 6 sections |
| `Stop` | When Claude finishes responding | **Blocks** if transcript contains architectural keywords but no vault file was written |

### Bypass (use sparingly — every bypass is logged)

```bash
CMA_VAULT_BYPASS=1 git commit ...           # both gates skip
CMA_VAULT_COMMIT_BYPASS=1 git commit ...    # only Hook 2 skips
CMA_VAULT_STOP_BYPASS=1 <action>             # only Hook 4 skips
```

Bypass events are appended to `O:/Temp/cma-vault-hook.jsonl` — frequent use is a signal the enforcement is mis-calibrated.

## Distinction from `cma.api.vaults`

| Concept | Module | What it stores |
|---|---|---|
| **Knowledge vault** | `docs/vault/` + `cma.vault` Python | Decisions, learnings, session context, cached docs |
| **Credential vault** | `cma.api.vaults` | Anthropic MAS credentials (one per `mcp_server_url`) |

When operator/agents say "the vault" in conversation, default reading: **knowledge vault** (this folder). Use "credential vault" or "MCP vault" to refer to `cma.api.vaults`.

## CLI surface

```bash
cma vault new-decision <slug>      # copy template + open in $EDITOR
cma vault new-learning <slug>
cma vault new-evaluation <slug>
cma vault new-incident <slug>
cma vault lint [PATH]              # frontmatter validation
cma vault index                    # regenerate _INDEX.md files
cma vault refresh-knowledge        # scrape Anthropic docs (curated 15)
```

See `cma vault --help` for full flag reference.

## Templating into consumer projects

`cma project init --with-vault` scaffolds this structure into any consumer project's `docs/vault/`. The vault is the foundational meta-system — every new cma-using project gets the same bench, tools, and light.
