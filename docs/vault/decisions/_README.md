# `decisions/` — Architectural Decision Records

> One file per decision. Dated. Frontmatter-typed. Cite-able. Never deleted —
> superseded.

## When to write an ADR

You write an ADR when **either** of the two triggers fires:

1. **Operator + agent deliberated alternatives** in conversation and chose one. The defining test: would a future reader of just the code be confused about why this path? If yes → ADR.
2. **A `### Decisions baked in` bullet is being added to CHANGELOG.md.** The Hook 2 PreToolUse gate enforces this: every new bullet must have a parallel ADR file staged in the same commit, or the commit is blocked.

## When NOT to write an ADR

- Bug fixes restoring documented behavior
- Lint / formatting / dependency bumps without behavioral implication
- Tests added for existing behavior
- "Code cleanup" with no observable change
- Doc-only updates that don't shift a decision

If you're unsure, file a `learning.md` first — promote to decision later if it crystallizes.

## How to write one

```bash
cma vault new-decision <kebab-slug>
# → creates 2026-05-20-<kebab-slug>.md, fills frontmatter, opens $EDITOR
```

The template lives at [`../_templates/decision.md`](../_templates/decision.md). It has six sections — fill at minimum: **Context, Options considered, Decision, Rationale, Trade-offs accepted**. Skip "Revisit trigger" only if the decision is genuinely stable.

## Filename convention

`YYYY-MM-DD-<kebab-slug>.md`

- Date is the day the decision was **made** (not the day it was written up).
- Slug is short, descriptive, no project codenames (this travels via `--with-vault`).
- ASCII only — shell-friendly across operator's OS surfaces.

## Status lifecycle

```
draft  →  active  →  superseded  →  archived
                  ↓
              (rarely)
```

- `draft` — being written; not yet load-bearing.
- `active` — current standing; cited by code / other ADRs.
- `superseded` — replaced. Must set `superseded_by:` + `superseded_reason:`. **Don't delete.**
- `archived` — historically interesting but no longer cited anywhere. Move to `_archive/` (when we have enough volume to warrant a subfolder).

## Revisit cadence

If an ADR's `created:` is >90 days old, the linter expects either:
- `reviewed_on: <recent date>` (we re-confirmed it), OR
- `status: superseded` or `archived` (it's no longer current)

This catches stale decisions before someone cites them as authority.

## The `_INDEX.md` file

Auto-generated by `cma vault index`. Don't edit by hand. Lists every ADR + status + created + last-reviewed.

## Why these are committed

- Cold-start agents read this folder when picking up the project.
- `manage_adr`'s 6-section summary is distilled FROM these ADRs.
- CHANGELOG can be squashed in future repo cleanups; ADRs survive.
